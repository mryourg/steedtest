# Speedtest

Консольный скрипт для замера скорости скачивания файла по HTTP(S) с помощью `requests`. Скрипт выполняет 10 последовательных GET-запросов, читает каждый ответ по частям и не сохраняет файл на диск.

## Локальный запуск

Требуется Python 3.10 или новее. Создайте виртуальное окружение и установите зависимость:

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install requests
```

### Windows (PowerShell)

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install requests
```

Запустите скрипт:

```bash
python speedtest.py https://example.com/file.bin
```

Если не передать URL, используется `SPEEDTEST_URL` из окружения или встроенный адрес `https://proof.ovh.net/files/10Mb.dat`. Перед замером скрипт выводит выбранный адрес:

```bash
python speedtest.py
```

## Настройка через переменные окружения

Шаблон `.env.example` содержит URL по умолчанию, число попыток, размер чанка и таймауты. Скопируйте его при необходимости:

```bash
cp .env.example .env
```

Файл `.env` не загружается автоматически. В Linux / macOS экспортируйте его значения перед запуском:

```bash
set -a
source .env
set +a
python speedtest.py https://example.com/file.bin
```

Для Docker передайте файл через `--env-file`:

```bash
docker run --rm --env-file .env speedtest https://example.com/file.bin
```

Без переменных окружения используются значения по умолчанию из `.env.example`.

## Запуск через Docker

Соберите образ:

```bash
docker build -t speedtest .
```

Запустите замер:

```bash
docker run --rm speedtest https://example.com/file.bin
```

На Linux рекомендуется использовать `--network host`, чтобы исключить влияние bridge-сети Docker на замеры пропускной способности:

```bash
docker run --rm --network host speedtest https://example.com/file.bin
```

URL может уже содержать GET-параметры — они будут сохранены. При выполнении команды URL с параметрами рекомендуется заключать в кавычки:

```bash
python speedtest.py "https://example.com/file.bin?version=2"
```

Пример итогового вывода:

```text
============================================================
Результаты замера:
============================================================
Успешных запросов: 10/10
Среднее время успешного запроса: 1.245 с
Общий объем скачанных данных: 100.000 МБ
Итоговая средняя скорость: 642.570 Мбит/с
============================================================
```

## Метрики

- **Среднее время успешного запроса** — суммарное время чтения тел успешных ответов, деленное на число успешных попыток. В него не входят DNS-резолв, TCP/TLS-хэндшейк и ожидание заголовков ответа (TTFB).
- **Общий объем скачанных данных** — сумма байтов всех успешных ответов в десятичных мегабайтах: `1 МБ = 1 000 000 байт`.
- **Итоговая средняя скорость** — `общее_число_байт × 8 / суммарное_время / 1 000 000`, в Мбит/с. Это общая пропускная способность по всем успешным попыткам, а не среднее арифметическое скоростей отдельных запросов.

Ошибочные попытки не учитываются ни в одной метрике. Если все 10 попыток завершились ошибкой, итоговые метрики не выводятся, а скрипт завершается с ненулевым кодом возврата.

## Обработка сетевых особенностей

- Тело ответа загружается со `stream=True` и `iter_content()` блоками по 64 КиБ. Данные не накапливаются в памяти и не записываются на диск.
- К каждому запросу добавляется уникальный параметр `_cb`, снижающий вероятность получения ответа из кэша CDN.
- Передается заголовок `Accept-Encoding: identity`. Если сервер все же возвращает сжатый ответ, попытка считается ошибочной: это исключает расчет скорости по распакованным байтам.
- Таймер запускается после получения заголовков, непосредственно перед чтением первого блока тела ответа.
- Для каждой попытки действует абсолютный лимит скачивания тела — 30 секунд. При его превышении соединение закрывается, а попытка исключается из расчетов.
- При наличии корректного `Content-Length` фактический объем ответа сверяется с указанным. Любое несовпадение, включая тихий обрыв соединения, делает попытку ошибочной.
- Дополнительно установлены таймауты `requests`: 10 секунд на подключение и 30 секунд на ожидание данных между операциями чтения.

## Тесты и проверки качества

В активированном виртуальном окружении установите инструменты разработки:

```bash
python -m pip install pytest ruff mypy types-requests
```

Запустите тесты чистых математических функций:

```bash
python -m pytest
```

Запустите Ruff, включая проверку форматирования:

```bash
python -m ruff check speedtest.py test_speedtest.py
python -m ruff format --check speedtest.py test_speedtest.py
```

Запустите строгую проверку типов:

```bash
python -m mypy --strict speedtest.py test_speedtest.py
```

Сетевые запросы в тестах не выполняются и не мокируются: `test_speedtest.py` проверяет только конвертацию единиц, расчет скорости и агрегацию статистики.
